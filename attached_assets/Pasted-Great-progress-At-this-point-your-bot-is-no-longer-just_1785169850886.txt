Great progress. At this point your bot is no longer just a scanner — it has the beginnings of a real monitoring system.

I would **not move to Smart Filters yet.** I would add **management commands first** because your database is starting to collect things users need to control.

Right now you have:

* `/watchlist` → view saved games
* 👀 Watch button → add tracking
* ❌ Ignore → block games

But there is no way to manage watched games after adding them.

## Next step: Add `/unwatch`

Have Replit build:

```text
/unwatch <game_id>
```

Example:

```
/unwatch 994732206
```

Bot:

```
✅ Removed Blox Fruits from your tracked games.
```

---

### Replit prompt:

```
Add an /unwatch command.

Requirements:

- Add a slash command: /unwatch game_id
- Remove that game from watched_games for the current user.
- If the user is not watching the game, return a helpful message.
- Keep all existing functionality unchanged.
- Add a /watched command that shows currently tracked games separately from /watchlist.
```

---

Why add `/watched` too?

Because your current naming is confusing:

`/watchlist` currently means saved bookmarks.

You should eventually have:

```
/saved
Shows bookmarked games

/watched
Shows actively tracked games

/ignored
Shows games you blocked
```

A cleaner product structure:

```
📚 Saved
"I like this game"

👀 Watched
"Track this game's growth"

🚫 Ignored
"Never show this again"
```
